# Architecture / 设计架构

## One canonical Skill / 唯一源码

仓库根目录 SKILL.md 是唯一核心指令；references/ 定义工作流；agents/openai.yaml 提供界面描述；assets/report-template.md 是输出模板；scripts/ 提供辅助工具。

## 阅读与教学流程

1. 核查论文全文、公式、图表、附录和源码的可访问范围。
2. 评估学术价值与零基础学习价值，设置 P0–P3 优先级。
3. 为各知识模块设置 M0–M4 掌握目标和 D0–D3 讲解深度。
4. 建立概念/角色表，区分执行者、程序、动作、数据、状态、环境和指标。
5. **目的先行**：讲核心部件前，先交代整体任务、当前流程位置、具体痛点、原有流程的局限和所需能力，然后才介绍术语。
6. **因果链解释**：讲清部件之前发生了什么、它具体做了什么、输出如何影响下一阶段。
7. 用同一个教学例子逐步追踪输入、执行者、操作、输出和状态变化。
8. 对回放/复用机制，先解释为什么需要再次使用历史信息，再精确区分读取、重放、重新执行、重新评估和重算。
9. 先解释数学对象，再引入公式；将论文事实、教学例子和推断分开。
10. 对可访问的源码建立论文公式/流程与文件函数的映射。
11. 审计证据、限制和学习目标。

## 清晰度设计

- 定义一个部件不等于解释了它的必要性；两者必须分别回答。
- “提高效率”“控制探索”“复用历史”等空泛说法必须拆成具体的工作、数据和步骤。
- 不虚构架构；教学上的功能拆分不代表独立模型或进程。
- 不跳过状态变化和上下游联系。
- 对没有实验或原文依据的“移除后会怎样”明确标记为推断。

## Capability boundaries

- Skill 指令不等于执行权限；宿主需要提供 PDF、浏览器、Git 或 Python 等工具。
- 可移植插件 ZIP 不等于安装完成。
- 源码静态分析不等于代码已运行。
- 结构性测试不等于科研正确性。

## Versioning

当前发行版本：1.5.0。修改 Skill 行为时更新 CHANGELOG；插件 ZIP 从唯一 Skill 源码自动构建。
