# Architecture / 设计架构

## One canonical Skill / 唯一源码

仓库根目录 SKILL.md 是唯一核心指令；references/ 定义具体工作流；agents/openai.yaml 提供 UI 描述；assets/report-template.md 作为输出模板；scripts/repo_inventory.py、scripts/validate_report.py 是可选的只读辅助工具。

所有发布包都由这些文件自动生成。scripts/build_plugin.py 将它们复制到 ZIP 的 skills/value-adaptive-paper-reading/ 路径；mobile-plugin/plugin.json 是插件元数据模板。

## 阅读流程

1. 原文核查：识别全文、公式、图表、附录和源码的可访问范围。
2. 论文学术价值与新手学习价值：P0–P3 优先级，不凭空判断项目相关性。
3. 掌握目标：分模块设置 M0–M4 和可验证达标标准。
4. 解释深度：根据重要性、知识依赖和目标，在 D0–D3 中分配篇幅。
5. 概念消歧：建立术语/角色台账，区分执行者、程序、策略版本、单次调用、动作、执行尝试、数据结构、状态、环境和指标；只使用论文实际支持的区分。
6. 操作过程追踪：D3 方法使用一个贯穿示例，按操作前状态、执行组件、输入、具体操作、输出、操作后状态和下一步可见信息逐步演示。
7. 在线/回放对照：分别说明真实执行和回放模式中哪些模型、评估器、工具被调用，哪些历史结果被读取或揭示。
8. 证据驱动教学：先讲动机与直觉，再讲形式化定义、公式和论文证据。
9. 代码映射（可选）：若论文与源码相关且可访问，定位官方实现、记录版本，并按学习价值讲解。
10. 审计与交付：记录无法读取的内容、未证实的主张、原文位置及自测目标。

## Clarity design / 清晰度设计

- 对象分类：角色/组件、可复用程序、一次性动作、数据产物、状态、环境、指标分别定义。
- 时间尺度：策略本身、策略版本、一次调用、一次决策、单个任务/尝试、一轮、完整运行分别解释（仅当论文实际存在这些层次）。
- 不虚构架构：教学上的功能拆分必须标明不是论文确认的独立模型或进程。
- 不跳过状态变化：每一步都交代输入、执行者、输出以及下游可见信息。
- 不混淆回放语义：明确区分重新生成、重新评估、读取、揭示、预测和重算。
- 公式先定义对象：每个符号映射到具体论文对象后才推导。

## Capability boundaries / 运行边界

- Skill 指令不等于执行权限。需要宿主工具才能获取 PDF、浏览网页、运行 Git 或 Python。
- 可移植插件 ZIP 不等于安装完成。用户还需使用宿主支持的渠道安装或通过 Plugin Creator 完成设置。
- 源码静态分析不等于代码已运行。默认不运行第三方代码。
- 结构性测试不等于科研正确性。仓库检查脚本不会判断 AI 生成报告的公式、数据或结论真伪。

## Versioning

仓库与插件包统一使用发行版本 1.4.0。改动 Skill 的行为时更新 CHANGELOG；打包不复制永久维护的第二份 Skill。
