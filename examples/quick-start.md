# Quick start examples / 使用示例

下面是可直接复制的调用语句。实际报告应标注论文全文可访问范围。

## 单篇论文（适合零基础）

\`\`\`text
$value-adaptive-paper-reading
请完整阅读这篇论文（如果全文可访问），先判断它对零基础读者的学习价值，
为不同内容设置掌握目标，并生成有原文依据的中文精读报告。
讲每个核心部件时，先讲整体任务、流程走到哪一步、遇到什么问题、
为什么需要这个部件，再介绍术语和输入输出。
不要只给部件定义，要讲清楚它为什么出现在这里，以及它让后续步骤能够做什么。
\`\`\`

## 讲清楚复杂算法或多 Agent 系统

\`\`\`text
$value-adaptive-paper-reading
请把我当成零基础读者。不要一开始就堆公式或组件名称。
讲每个关键部件时必须按“整体目标—当前流程—具体痛点—没有它会怎样—
白话说明它解决什么—技术名称—实际机制—前后步骤关系”的顺序。
先建立术语表和角色表，区分模型/Agent、可复用策略程序、策略版本、
一次调用、调用输出的动作、一次实际执行、一轮决策和完整运行
（只在论文确实区分这些层次时使用）。
用一个贯穿始终的例子逐步演示状态、执行者、输入、操作、输出和变化。
如果有回放机制，先解释为什么后续步骤需要再次使用历史探索信息，
再精确说明复用的是什么、哪些步骤因此可以跳过、哪些仍需重新执行。
公式必须在所有符号的具体指代说清楚后再引入。
所有教学虚构数字标记为“教学示例，非论文实验数据”。
\`\`\`

## 多篇论文的学习顺序

\`\`\`text
$value-adaptive-paper-reading
我提供了三篇论文链接。先绘制技术关系和前置知识依赖，
逐篇评估学习价值，推荐阅读顺序。不要给所有论文平均分配篇幅。
\`\`\`

## 有源码的算法论文

\`\`\`text
$value-adaptive-paper-reading
请精读论文，并在发现可信的官方代码仓库后，分析核心模型、损失函数和训练循环。
讲源码模块前先说明它在整体执行流程中解决什么问题，再说明函数输入、
操作、输出、调用者和状态变化。建立公式与文件/函数映射，标注版本。
默认只静态阅读，不安装依赖、不运行第三方代码。
\`\`\`

## 读完后验证理解

\`\`\`text
$value-adaptive-paper-reading
根据这篇报告的 M2 学习目标，给我设计概念解释题、简单计算题和方法追踪题。
检查我能否说明每个核心部件为什么需要、它解决什么问题、具体如何工作。
提供答案和评分准则，但不要在我作答前把我标记为已掌握。
\`\`\`

## 用户反馈“没看懂”时重新讲

\`\`\`text
$value-adaptive-paper-reading
我没看懂刚才的解释。不要直接重复术语定义。
先从整个系统想完成什么开始，指出流程走到哪里、遇到了什么具体问题、
如果没有这个部件原本要怎么做、为什么这会造成困难。
然后再讲这个部件的白话目的、准确术语和实际工作过程。
用同一个例子一步步走完，并区分论文事实与教学推断。
\`\`\`
